# VLM for Insulator Defect Detection

Итоговый чистый репозиторий исследования по применению визуально-языковых моделей для анализа дефектов изоляторов.

## Краткий итог

В проекте проверялась идея использования VLM в pipeline инспекции изоляторов:

```text
изображение
→ detector / crop
→ DINOv2 classifier
→ VLM review/safety layer
→ автоматическое решение или ручная проверка
```

Главный вывод: VLM не стала лучшей заменой DINOv2-классификатора по raw accuracy, но дала пользу в другой роли -- как дополнительный слой проверки, риска и безопасности поверх DINOv2.

DINOv2 отвечает на вопрос:

```text
какой класс?
```

VLM помогает ответить на вопрос:

```text
можно ли доверять этому автоматическому решению без человека?
```

## Основные найденные преимущества VLM

1. **Проверка рискованных случаев**
   VLM помогает выбирать, какие случаи отправить на ручную проверку. В экспериментах DINO+VLM улучшил AUPRC для поиска ошибок примерно с `0.41` до `0.54`, а accepted accuracy при `10% review` выросла примерно с `0.6731` до `0.7115`.

2. **Фильтрация ложных тревог**
   VLM помогает находить случаи, где DINOv2 слишком резко объявляет дефект на нормальном изоляторе, особенно ошибки вида `insulator_ok -> defect_flashover`.

3. **Проверка спорных flashover-предсказаний при малом бюджете ручной проверки**  
   На поднаборе данных, где DINOv2 предсказал `defect_flashover`, VLM использовалась как дополнительный проверяющий слой: действительно ли на изображении видны признаки flashover. При одинаковом малом бюджете ручной проверки `4/36` VLM поймала больше ложных тревог, чем проверка только по margin: `0.2308` против `0.0769`, и при этом лучше сохранила настоящие flashover: `0.9524` против `0.8571`.

4. **Фильтрация плохих crop и отказ от ненадёжного автоматического решения**  
   Обычный классификатор закрытого набора классов обязан выбрать один из известных классов даже тогда, когда crop плохой: изображение размыто, объект обрезан, плохо виден или почти отсутствует. VLM может выполнить другую роль: оценить, пригоден ли crop для автоматической классификации, и отправить плохой случай на ручную проверку. В экспериментах обычный классификатор ошибочно принимал плохие crop почти всегда: false accept около `1.0`, а строгий VLM-режим безопасности снижал этот показатель примерно до `0.0133`.

5. **VLM как слой проверки и сопровождения решения**  
   VLM полезна для построения более практичного процесса инспекции: она может добавлять флаг необходимости ручной проверки, краткую причину сомнения, признак плохого crop и сигнал возможной ложной тревоги. Это превращает систему из простого классификатора в более управляемый пайплайн: DINOv2 предсказывает класс, а VLM помогает решить, можно ли принять это решение автоматически или лучше показать случай инспектору. В перспективе такой слой можно использовать для очередей ручной проверки, карточек инспектора и анализа типичных ошибок системы.
