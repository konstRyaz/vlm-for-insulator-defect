# Постановка задачи

## Объект исследования

Объектом являются изображения изоляторов ЛЭП. Для каждого найденного изолятора требуется получить структурированное описание состояния: нормальный объект, след flashover, механическое разрушение или неопределённый случай.

## Основные классы

В текущей разметке используется coarse-level классификация:

| Класс | Смысл |
|---|---|
| `insulator_ok` | визуально целый изолятор без явных признаков дефекта |
| `defect_flashover` | следы перекрытия/подгорания, тёмные дорожки, flashover-like surface trace |
| `defect_broken` | скол, недостающий фрагмент, нарушенная геометрия |
| `unknown` | изолятор виден, но признаков недостаточно для уверенного решения |
| `other` | объект не соответствует целевым классам |

Для отчётных метрик основной интерес представляют первые три класса. `unknown` и `other` нужны, чтобы модель могла корректно отказаться от чрезмерно уверенного ответа.

## Исследовательский вопрос

Главный вопрос текущего этапа: где находится основной предел качества — в детекторе, в геометрии crop или в семантическом распознавании дефекта на crop?

Для ответа задача разделена на два режима:

- **Stage 3:** модель получает crop по ground-truth bbox. Это проверка VLM/классификатора без ошибки детектора.
- **Stage 4:** модель получает crop, построенный по предсказанию детектора. Это реальный detector-to-VLM сценарий.

## Текущий вывод

На текущем валидационном срезе детектор и crop-геометрия не являются главным ограничением: большинство объектов сопоставляются корректно. Основная ошибка возникает на уровне семантики crop, особенно на границе `insulator_ok` / `defect_flashover`.
